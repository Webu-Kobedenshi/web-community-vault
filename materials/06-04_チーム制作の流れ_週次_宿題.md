## 1. これからのチーム制作の流れ（7分）

**話すこと：**

### ゴールはひとつ

- 「**7月16日に、自分たちのWebアプリを “公開URLで実際に触れる状態” にして発表する**。これがゴール。機能は欲張らず、**1〜2個に絞ったものがちゃんと動く** ことを最優先にします」
- 「夏休み後にもう一回チーム制作があります。だから今回は **“チーム開発とWebの仕組みを一周体験する”** のが本当の目的。完璧なプロダクトを作る回ではない」

### どうやって作るか

- **AIで作る**。AntiGravity / Gemini / Claude を使って、コードを書いてもらいながら進める。「マクロにコードを完全理解する」より「**AIを使ってWebアプリを動かしきる**」が今回の目標。
- **活動日（毎週木曜）＝全員が顔を合わせる日**。コードを書く作業は活動日以外にもやってOK。活動日は「集まって相談・統合・詰まり解消」に使う。

### 進め方のルール（ガードレール）

- **リポジトリはチームに1つ（モノレポ）**。`/frontend`（React）と `/backend`（Express）を同じリポジトリに入れる。
- **作業はGitHub Issueで管理**。「やること」をIssueに分けて、誰がやるか決める。
- **GitHub Flow**：Issueごとにブランチを切る → 書く → Pull Request → マージ → `main` がRenderに自動デプロイ。（第4回の「GitHubしりとり」でやったPRの流れそのまま）
- **`main` は壊さない**。`main` は公開デモに直結するので、直接pushはしない。マージの運用は各チームに任せます。
- **環境構築**：代表がテンプレ環境を作り、メンバーはそれをcloneして **Getting Started** の手順で各自セットアップ。開発は **WSL2（Linux）＋ mise**、DBは **Docker Compose の PostgreSQL**。
    - 「環境構築は来週(6/11)に全員でやります。今日は “そういう流れ” とだけ理解すればOK」

> **つまずき対策**：細部は今日は詰めない。「Issueで分けて、ブランチ切って、PRでマージ、mainがデプロイ」の4語だけ持ち帰らせる。
