    第4回活動：GitHub しりとり & デザインスプリント¶

    第4回活動を 神戸電子専門学校 管理棟 L教室 で開催しました。前半は前回の Git・GitHub ハンズオンの定着を狙った GitHub しりとり、後半は前回予告していた デザインスプリント です。声を出してアイデアを揉む活動なので、今回は OPTiM Club KOBE ではなく学校の教室を借りて実施しました。

    基本情報¶

    項目 内容
    日時 2026年5月28日（木） 15:30〜17:10
    場所 神戸電子専門学校 管理棟 L教室（第1回の教室の向かい）
    メイン GitHub しりとり / デザインスプリント（途中まで）

    学校内での開催だったため、活動時間は前回より短い 15:30〜17:10 でした。

    タイムスケジュール¶

    時間（実際） 内容
    15:30〜16:00頃 GitHub しりとり（概念説明・準備・ハンズオン・振り返り）
    16:00頃〜17:10 デザインスプリント（概念説明 → チーム作業）

    各セクションの様子¶

    GitHub しりとり（15:30〜16:00頃）¶

    メイン担当は 服部潤一（じゅん）。前回の Git・GitHub ハンズオン1回だけでは「使えるレベル」までは届いていなかったので、その定着のために用意したのが GitHub しりとりです。チーム内で順番に Pull Request を出し合い、しりとりのように繋いでいくワークです。

    • スライド：Git ハンズオン スライド p52〜最後
    • 手元資料：Git ハンズオン教材（Zenn Book）13章

    予定と実際¶

    当初は 15:15〜15:20 開始 → 25分で完了 という想定で、内訳は以下の通りでした。

    フェーズ 予定 実際 メモ
    概念説明 5分 約5分 ほぼ予定通り
    Pull Request の準備 5分 9〜10分 各チームが準備で手こずり超過
    手を動かす（ハンズオン） 10分 13分 1周回りきらず3分延長
    振り返り 5分 数分 —

    実際には開始が 15:30 にずれ込み、各フェーズも予定を超過。チーム2は1周回りきらず、6人中5人しか操作できないまま ハンズオン時間が終了しました。結果、GitHub しりとり全体が終わったのは 16時過ぎ でした。

    デザインスプリント（16:00頃〜17:10）¶

    後半は、これからチーム制作で作るアプリのアイデアをチーム内で揉むための デザインスプリント。Google が提唱するアイデア創出ワークフローの簡略版です。

    • スライド：デザインスプリント スライド（Canva）
    • 手元資料：失敗しない！アイデア出し方法　Design Sprint 簡略版（Zenn / マメ）

    概念説明は3分ほどで切り上げ、すぐにチームに分かれて作業へ。ホワイトボードと付箋 を使い、

    1. 個人でアイデアを出す
    2. それぞれ発表する
    3. 似たアイデアをグループ分けする
    4. 投票する
    5. 投票結果をもとに方向性を決める

    といったフェーズを順に進めました。

    良かった点：フェーズごとにスライドを分けていた¶

    進行で効いたのは、フェーズごとにスライドを分けていた ことです。「今この瞬間に何をやればいいのか」が常に画面に出ているので、チームも運営も迷わず進められました。

    反省点¶

    時間の見積もりが甘く、絞り切るところまで行けなかった¶

    正直に言うと、時間の予算が足りませんでした。当初は「1時間ちょい〜1時間半あれば、解決策を1つに絞り切るところまでいける」と見積もっていたのですが、実際には 第2フェーズの「なぜ私たちは何をすべきなのか？」という問いを立てるところまで しか進みませんでした。

    アイデア出しや話し合いの中身についても、運営の手応えとしては「これだ」という納得感のあるアウトプットまでは届いていない感覚で、ここはワークの設計・ファシリテーションともに次回への課題です。

    続きをオンラインに回す判断・日程調整¶

    デザインスプリントをこれ以上長引かせたくなかったため、残りはオンラインで続きをやる ことにしました。ただ、ここの運営判断に反省があります。

    本来は その場で運営がオンライン開催の日程を決め切ってしまうべき でした。しかし時間に追われ、判断もうまく下せず、結局 Discord の調整さんで日程を取る 形に。

    その調整さんも、チーム2はすぐ返信が集まった一方、チーム1はなかなか集まりませんでした。「Discord をあまり見ていないメンバーが多いんだな」という気づきとともに、日程調整に思いのほか手間取りました。次回以降は、続きが発生しそうな活動では、その場で次回日程を確定させてから解散する 運用にしたいです。

    次回予告：デザインスプリントの続き（オンライン）¶

    デザインスプリントの残りは、チームごとにオンラインで実施します。

    • チーム2：5月30日（土）にミーティング実施済み
    • チーム1：6月2日（火）に実施予定

    オンラインでのデザインスプリントにも振り返り・反省点がいくつもあるのですが、チーム1がまだ完了していない ため、両チームが終わってから改めて別記事としてまとめる予定です。

    まとめ¶

    • 第4回は学校（管理棟 L教室）で開催。前半 GitHub しりとり／後半 デザインスプリント
    • GitHub しりとりは各フェーズが予定超過。チーム2は6人中5人までしか操作できず16時過ぎに終了
    • デザインスプリントはフェーズごとのスライド分割が好評。一方で時間見積もりが甘く、絞り切るところまでは未到達
    • 続きはオンラインへ。その場で日程を確定できず調整さん運用になった点が反省。チーム1（6/2）完了後に別記事で報告します
